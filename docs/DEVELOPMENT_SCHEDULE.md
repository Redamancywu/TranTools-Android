# TranTools 开发排期清单

## 1. 当前完成度判断

### A. 已较完整

- 文本翻译：已完成主要闭环，剩余是体验优化与语言包细节
- 拍照翻译：已完成 CameraX、OCR、叠层和分享，剩余是历史实体拆分与高阶增强
- Wiki 浏览：已完成搜索、分类、详情、收藏、最近浏览
- 历史记录：已完成基础浏览、过滤和回填

### B. 中等完成度

- 语音翻译：已有系统 ASR + TTS + 翻译闭环，但离线兜底不足
- 设置页：视觉和入口已完成，但资源管理此前偏假实现，现已开始接真实模型下载链路
- Nearby / Gems：已有 POI 列表、详情、收藏、距离排序，但缺离线地图底图和地图联动

### C. 完成度最低

- 端侧 RAG：此前只有关键词召回和模板拼接，目前已补统一检索编排，但仍缺数据库索引层
- 本地 AI 助手：现已补真实 MediaPipe LLM 接口和模型包下载链路，但仍缺流式输出、能力探测、设备分级
- 资源包系统：语言包较真实，知识包、地图包、模型包仍需统一化

## 2. 优先级建议

### P0：尽快补齐主价值

- 接通真实端侧 LLM 推理
- 模型包下载、落盘、删除、状态展示
- Chat 优先使用本地检索 + 本地 LLM 回答
- Wiki / Chat 共用检索层，保证引用来源一致

### P1：把 MVP 主闭环做扎实

- Wiki / POI 建立 Room + FTS 索引
- Nearby 接离线地图底图
- 语音翻译补离线 ASR fallback
- 设置页补知识包管理与清空历史入口

### P2：向产品化演进

- 流式回答
- 模型初始化预热
- 设备能力检测和模型分级
- 多模型包切换
- 背景下载与恢复

## 3. 分阶段排期

### Phase 4A：本地检索与助手底座

- 统一 `RetrievalEngine`
- 统一 `ChatCoordinator`
- Chat / Wiki 共用来源卡片与建议问题
- 交付标准：无模型也能给出更稳定的本地检索答案

状态：已完成第一版

### Phase 4B：真实端侧 LLM

- 接入 MediaPipe LLM Inference
- 配置首个 Qwen2.5-1.5B-Instruct LiteRT 模型包
- 支持模型下载、删除、路径管理、错误回退
- 交付标准：Chat 在模型包 ready 时优先使用本地 LLM

状态：本次已完成第一版接入

### Phase 4C：真实 RAG 数据层

- Wiki 建 `WikiArticleEntity + WikiArticleFtsEntity`
- POI 建 `PoiEntity`
- Query 走 FTS + 标签 + 标题加权 + 规则重排
- 交付标准：摆脱纯 assets in-memory 检索

状态：未开始

### Phase 5A：离线地图

- 引入 MapLibre
- 城市包包含离线底图和 POI
- Gems 做地图和列表联动
- 交付标准：用户可离线看地图上的本地 POI

状态：未开始

### Phase 5B：离线语音增强

- 语音识别离线 fallback
- 语言与包状态联动
- 交付标准：弱网环境下语音翻译仍可用

状态：未开始

## 4. 这次改动后的下一步建议

1. 先验证模型包下载、初始化和回答体验
2. 然后把 Wiki / POI 检索迁移到 Room + FTS
3. 再做流式输出和设备分级
4. 最后接离线地图底图
